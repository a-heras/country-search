# Country Search — Design

## 1. Отмена устаревших запросов

### Проблема

При вводе `sp` → `spain` два запроса летят параллельно. Если `sp` ответит
позже `spain`, его результат перезапишет на экране более свежий. Это гонка
устаревших ответов — без явной отмены она неизбежна.

### Решение: `AbortController`, а не «флаг актуальности»

Используем **реальную отмену** через `AbortController`, а не фильтрацию
постфактум по таймстампу или флагу `isLatest`. Причины:

1. **Сеть и CPU.** Отменённый запрос действительно прерывается — экономия
   трафика и времени. Флаг же позволяет запросу завершиться и просто
   выбрасывает результат.
2. **Гарантия порядка.** `fetch` с `signal` отклоняет промис с `AbortError`
   ровно в момент `abort()`. Нет окна, когда ответ уже пришёл, но ещё не
   отфильтрован.
3. **Требование задания.** Прямо запрещено «маскировать гонку костылём
   вида „показывать только самый последний полученный ответ по таймстампу“».

### Где именно

**`src/countrySearchController.ts`** — держит текущий `AbortController`:

```ts
function cancel(): void {
  if (current !== null) {
    current.abort();
    current = null;
  }
}

async function search(query: string): Promise<Country[] | null> {
  cancel();
  const controller = new AbortController();
  current = controller;
  try {
    const result = await searchCountries(query, controller.signal);
    if (current !== controller) return null;
    return result;
  } catch (err) {
    if (isAbortError(err)) return null;
    throw err;
  } finally {
    if (current === controller) current = null;
  }
}
```

**`src/main.ts`** — отмена на **каждом** `input`, а не только когда debounce
фактически запускает новый запрос:

```ts
input.addEventListener('input', () => {
  const query = input.value;
  controller.cancel();
  debouncedSearch(query);
});
```

Если отменять только внутри `debounce`-колбэка, между вводом и фактическим
запуском нового запроса проходит `delay` мс — за это время устаревший ответ
успевает прилететь и отрендериться. Поэтому `cancel()` стоит в `input`-
обработчике.

### Различение ошибок

В `catch` (`main.ts` и `countrySearchController.ts`):

| Тип                      | `name`         | Что делаем                           |
| ------------------------ | -------------- | ------------------------------------ |
| Наша отмена              | `AbortError`   | Молчим, `return null`                |
| Таймаут                  | `TimeoutError` | Показываем ошибку с «Повторить»      |
| HTTP 4xx/5xx (кроме 404) | `HttpError`    | Показываем ошибку с «Повторить»      |
| 404 (нет совпадений)     | —              | `[]`, показываем «Ничего не найдено» |
| Сеть/CORS                | `TypeError`    | Показываем ошибку с «Повторить»      |

`AbortError` и `TimeoutError` — оба `DOMException`, но **разные `name`**.
Это принципиально: отмена своей же операции — не ошибка пользователя,
таймаут — ошибка.

### Таймаут

В `src/searchCountries.ts`:

```ts
const combined = AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)]);
```

`AbortSignal.any` компонует пользовательский сигнал и таймаут в один.
`fetch` отклоняется с тем `reason`, который сработал первым:

- `controller.abort()` → `DOMException { name: 'AbortError' }`;
- `AbortSignal.timeout` → `DOMException { name: 'TimeoutError' }`.

## 2. Обоснование задержки debounce — 300 мс

- **0 мс (без debounce):** каждый символ — запрос. Ввод `spain` = 5 запросов
  вместо 1. На публичном API это быстро приводит к 429 (rate limit), плюс
  мигание индикатора загрузки.
- **< 200 мс:** всё ещё слишком много запросов при быстром наборе —
  debounce не успевает «схлопнуть» ввод.
- **300 мс:** золотая середина для «живого поиска». Пользователь не замечает
  задержки (порог восприятия ~200–300 мс), но серия быстрых нажатий
  схлопывается в один запрос.
- **> 500 мс:** появляется ощущение «тормозит» — набираешь, а результата нет.
  Пользователь начинает думать, что сломалось.

Итог: **300 мс** — баланс между отзывчивостью и нагрузкой на API.

## 3. Сложность

### `mapCountryResponse(raw)`

**O(L + B + C)**, где:

- `L` — число языков страны (обычно 1–4, максимум ~10);
- `B` — число границ (обычно 0–15);
- `C` — число валют (обычно 1–2).

Поля `name`, `capital`, `region`, `population`, `area` читаются за **O(1)**.
Преобразования `languages.map(...)` и `currencies.map(...)` линейны по
длине соответствующих массивов. `borders` и `timezones` копируются через
`?? []` — O(1) на ссылку.

**Итог: O(n) по размеру входного объекта**, где n — суммарное число
элементов в `languages`, `currencies`, `borders`. Для отдельной страны это
фактически **O(1)** — константа.

Память: **O(L + B + C)** на новый `Country`-объект (не мутируем `raw`).

### Кэш и дедупликация (если реализованы)

**Кэш по строке запроса:** `Map<string, Country[]>`.

- `get`: **O(1)** в среднем (хэш-таблица).
- `set`: **O(1)** в среднем.
- Память: **O(k)**, где k — число закэшированных запросов.

**Дедупликация in-flight:** `Map<string, Promise<Country[]>>`.

- Проверка «есть ли уже такой запрос в полёте»: **O(1)**.
- Присоединение к существующему промису: **O(1)** — возвращаем ту же ссылку.
- Память: **O(m)**, где m — число одновременных уникальных запросов
  (обычно 1–2).

## 4. Принципы чистого кода

### Единственная ответственность (SRP)

- **`src/debounce.ts`** — только debounce, ничего про сеть/DOM.
- **`src/searchCountries.ts`** — только HTTP-запрос + проверка `response.ok`
  - `404`-семантика. Не знает про UI.
- **`src/mapCountryResponse.ts`** — только маппинг `RawCountry → Country`.
  Чистая функция, не мутирует вход.
- **`src/countrySearchController.ts`** — только управление отменой и
  текущим запросом.
- **`src/ui/*`** — только рендер, никакой логики запросов.
- **`src/main.ts`** — «клей»: подписывается на `input`, вызывает контроллер,
  решает, какое состояние показать.

### Чистые функции

- **`mapCountryResponse`** — детерминированная, без побочных эффектов,
  не мутирует `raw` (покрыто тестом «не мутирует входной объект»).
- **`debounce`** — возвращает новую функцию, состояние таймера замкнуто
  внутри, снаружи не видно.
- **`formatCurrency`** (`mapCountryResponse.ts`) — вынесена как чистая
  функция форматирования.

### Обработка ошибок через типы

- **`HttpError`** (`src/httpError.ts`) — свой класс с полем `status`.
  Позволяет отличить HTTP-ошибку от сетевой/отмены.
- **`isAbortError`** (`countrySearchController.ts`) — отдельная функция-
  предикат, читается как намерение.

### Разделение состояний UI

`src/ui/renderStates.ts` — три отдельные функции:

- `renderLoading()`;
- `renderEmpty()` (404 — не ошибка);
- `renderError(onRetry)`.

`src/main.ts` выбирает одно из состояний по результату `controller.search`:

- `null` → ничего (отмена);
- `[]` → `renderEmpty()`;
- `Country[]` → `renderResults()`;
- `throw` → `renderError()`.

### Безопасный DOM

`src/ui/dom.ts` — единственное место, где создаются элементы. Хелпер `el`
работает через `document.createElement` + `textContent` + `appendChild`.
**Никакого `innerHTML`/`insertAdjacentHTML`** — XSS невозможен по
построению, даже если API вернёт `<script>` в названии страны.

### Тестируемость

Вся логика (`debounce`, `searchCountries`, `mapCountryResponse`,
`countrySearchController`) **не зависит от DOM** и тестируется в Node с
мок-`fetch`. Тесты — 25 штук, включая тест на гонку запросов с мок-`fetch`,
который реагирует на `signal` и отклоняется с `AbortError` при `abort()`.
